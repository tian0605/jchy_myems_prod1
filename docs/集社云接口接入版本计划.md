## 1. 本次版本范围

本次仅接入以下接口：

- `POST /NH2/AmmeterBasicInfo`：查询电表档案。
- `POST /NH2/ElectricQuantity`：查询15分钟电量。

目标设备规模约70多台。电量以15分钟为粒度，每小时采集已结束的上一小时数据；供应方告知数据延迟约20至30分钟、接口每分钟最多调用10次、空电表地址可查询全部设备。电量历史一般可查约一年，日数据可查约三年。

本计划结合代码审查、Apifox公开规范和2026-10-01的初步接口样本。样本是单次测试，不能替代生产契约确认和持续运行验证。

### 1.1 已确认的电量取值规则（2026-10-14更新）

- 电量接口入参固定为`valueType=SJZ`（实际值），15分钟粒度使用`dateType=mi15`。
- 出参以正向有功示值`ZYGDNSZ`作为本次有效的电量累计读数；请求值类型与响应取值字段分别定义，不因为使用示值字段而把入参改为`SSZ`。
- `ZYGDN`不作为本版本主链路用电量计算依据；其他电量及示值字段保留原始审计信息，不与`ZYGDNSZ`混算。
- 小时用电量由累计读数按时间边界差分产生，不能直接求和四个`ZYGDNSZ`读数。复用Normalization前必须验证其边界归属、缺数和补数处理，不能把现有差分实现视为无需调整即可正确。

### 1.2 已确认的工作台、完整性及部署要求

- 本版本必须在后台管理员端提供“数据采集任务工作台”，不仅是只读日志或数据源配置页。
- 对纳入采集范围的每台电表，每个应到的15分钟时刻都必须有接口返回记录。零用电、读数不变或设备离线不能自动作为允许缺记录的理由；缺失时必须在工作台显示告警。
- 新的数据采集服务必须通过独立容器启动和运行，不嵌入API、MQTT、Modbus或聚合容器执行。

## 3. 调研问题结论

### 3.1 基础表和数据表

MyEMS已有本地电表`tbl_meters`、测点`tbl_points`、电表与测点关联`tbl_meters_points`，以及历史测点值`tbl_energy_value`和业务小时结果`tbl_meter_hourly`。它们分别用于本地业务电表、单测点和现有小时能耗处理，不包含一套完整的集社云设备身份、完整15分钟多字段原始返回和任务执行历史模型。

建议新增以下数据模型，而不是把集社云设备直接覆盖进通用`tbl_meters`：

1. **外部电表映射表**：数据源、MyEMS `meter_id`、`point_id`、集社云`ID`、唯一`Address`、区域信息及同步时间；对同一数据源的外部设备ID和地址增加唯一约束。记录初始化任务、配置就绪状态、采集启用状态及生效时间，支持自动初始化和后续人工配置。
2. **15分钟原始电量暂存表**：本地电表映射、外部ID/地址、`ReadingDate`、`dateType`、`valueType`、`ZYGDNSZ`有效累计读数、其他返回字段、来源任务及原始响应必要审计信息。`valueType`本版本固定`SJZ`，有效读数采用Decimal精度存储。唯一业务键建议为“数据源 + 外部地址 + 时间点 + 粒度 + 值类型”，重放时使用upsert。
3. **采集运行/补数记录表**：任务类型、查询时间范围、状态、调用次数、返回/新增/重复/缺失数量、重试次数、错误信息和起止时间。任务定义可由数据源配置承担，运行历史独立保存。
4. **数据完整性告警记录**：保存数据源、任务、外部电表地址、缺失的15分钟时刻、异常类型、首次/最近发现时间、恢复时间及管理员确认信息。按数据源、电表地址、时刻和异常类型建立唯一约束，防止重查产生重复活动告警；与任务运行/补数记录关联。

`tbl_data_sources`可继续承载数据源元信息和连接配置的现有概念，但不是接口响应表，也不具备足够的任务执行历史。`tbl_energy_value`仅适合单个点值的历史曲线，不能直接表达API返回的多个有功/无功区间值与累计示值。`tbl_meter_hourly`可继续作为小时结果目标；它目前不是15分钟原始表。现有历史值表和小时表均未在安装SQL中定义相关时间业务键唯一约束；添加约束前应审查并处理现存重复数据。

按已确认的`ZYGDNSZ`累计读数规则，可将该字段映射到`ENERGY_VALUE`测点并幂等写入`tbl_energy_value`；完整API返回仍由原始暂存表保存。需明确集社云测点的处理归属，防止旧Normalization流程与新处理流程同时写入同一小时结果。

### 3.2 采集运行位置与前端

当前`myems-modbus-tcp`和`myems-mqtt`分别承担协议采集；`myems-normalization`将测点历史读数归一化；`myems-aggregation`执行计费、碳排等后续计算。代码中没有现成的集社云HTTP轮询采集器。

本次确定新增独立的集社云HTTP采集容器，负责定时调度、HTTP调用、供应方限流、失败恢复和完整性检查，不在MQTT、Modbus、API或聚合容器中启动采集循环。提供独立镜像构建、容器编排服务、启动命令、重启策略、运行日志及健康检查；工作台区分“容器/采集服务健康”和“接口请求成功/数据完整”。服务应复用数据库配置模式，但以环境变量/密钥管理注入API Key，不能将密钥暴露在前端或提交到版本库。

现有Admin可管理数据源和测点，也显示数据修复文件状态；没有通用接口采集任务运行历史、缺数监控及补数操作页面。本版本必须在Admin新增“数据采集任务工作台”，由管理API、持久化任务状态和告警记录支持，具体范围见3.5节。

### 3.3 入库、去重和下游处理

现有`tbl_energy_value`和`tbl_meter_hourly`没有对应时间点的唯一约束；MQTT历史点值写入与归一化小时结果均采用普通插入。因此不能将当前链路视作已有重试幂等机制。

建议采用以下流程：

1. 通过档案初始化任务按数据源和`Address`创建或复用本地电表、测点及映射（见3.6节）；常规电量任务仅使用已确认且启用的映射。未初始化、存在冲突或无法映射的返回记录保留原始数据并提示配置异常，禁止按名称模糊自动绑定。
2. 每次成功获取的15分钟数据先写入暂存表，使用业务唯一键upsert；记录缺失地址和异常时间点。
3. 请求固定`valueType=SJZ`，提取`ZYGDNSZ`映射到本地`ENERGY_VALUE`测点。校验读数为有效数值；缺失、null及解析失败不能转为零。相邻有效读数不变可表示零用电，但读数回退、换表、清零或异常跳变需记录异常并按确认的规则处理。
4. 按`ReadingDate`检查15分钟采样覆盖和小时计算所需的边界读数。实测查询中每个点仅返回29台，档案有33台；缺少点的电表/小时标记为不完整，不能静默当零，也不能算作完整小时。
5. 以累计读数差分生成小时用电量，结果写入MyEMS `tbl_meter_hourly`，再由已有计费和碳排任务处理。若`ReadingDate`表示时刻累计值，12:00至13:00小时用电量为`R(13:00)-R(12:00)`，中间15分钟点用于完整性和异常校验。本次样本仅有12:00、12:15、12:30、12:45，不能仅凭这四个读数认定完整小时用电量；需确认时间标签语义并补取对应边界读数。
6. 复用并适配Normalization累计读数差分链路，验证时间边界归属、初始化基线、迟到数据和缺数处理；禁止直接求和`ZYGDNSZ`或改用`ZYGDN`替代。集社云测点未取得完整数据前不得由旧流程自动补零并推进处理时间。
7. 迟到数据或补数覆盖已完成的小时后，重算受影响的相邻差分区间和小时业务值；同时显式触发受影响的计费/碳排历史结果重算，不能假设增量聚合器会自动修正旧区间。

测试里样本地址缺失情况较一致，但需继续确认这4台是停用/无数据还是接口遗漏。按本版本要求，纳入采集范围的电表仍应逐时刻返回记录，上述缺失必须产生工作台告警。若业务明确停采，应由管理员修改该电表的采集范围及生效时间并保留审计；不能因接口未返回或离线状态而自动从完整率分母剔除，也不能通过停采清除历史缺失记录。

### 3.4 初始化和补数

本次必须包含首次初始化与持续补数能力：

- 首次任务：通过档案初始化任务批量生成计量表、`ZYGDNSZ`累计读数测点、表点关联和外部映射，管理员补充或确认业务配置后启用采集（见3.6节）；历史电量初始化作为独立任务，回补时同时获取业务起点及终点计算所需的边界/基线读数，无基线时不能把首笔累计值当作用电量。
- 常规轮询：每小时采集刚结束的小时，计划在结束后35至40分钟运行；每次重查最近若干小时以覆盖20至30分钟延迟，并确保查询范围涵盖差分所需的边界读数。若接口不含结束时刻，需延伸查询范围或在后续任务补齐，不能假定单小时四条记录已足够。
- 失败重试：遵循供应方每分钟不超过10次的限制，设置服务级限流、指数退避和随机抖动；不能让并行补数绕过全局限流。
- 历史补数：任务支持开始/结束时间与状态追踪，按供应方可查范围分片；15分钟数据通常约一年，日数据约三年，三年日数据不能还原为15分钟序列。
- 数据修订：同一业务键再次返回不同值时upsert并记录变更来源，重新生成受影响的小时及下游聚合。

### 3.5 后台管理员数据采集任务工作台

工作台是本版本必交付功能，入口位于后台管理员端，管理API执行服务端管理员权限校验。API负责任务配置和提交操作，独立采集容器领取并执行任务；不在Web请求中同步拉取供应方数据。

| 功能 | 必须支持的内容 |
|---|---|
| 总览 | 采集服务健康、任务启停状态、最近/下次计划执行时间、最后完整采集时间、活动告警数、应到/实到/缺失记录数及完整率 |
| 任务管理 | 档案同步、常规电量采集、初始化和历史补数任务清单；配置采集设备范围和起始时间，启用/暂停后续调度，手动触发、失败重试；保留操作者和变更记录 |
| 电表档案初始化 | 调用档案接口，预览并选择待初始化电表，批量设置必填业务配置，创建或复用计量表、测点、表点关联及外部映射；显示新增/复用/冲突/失败数量和逐表配置入口 |
| 执行明细 | 查询时间范围、排队/运行/失败/部分完成/完成状态、执行起止时间、重试次数、接口错误、返回/新增/更新/重复/无效/缺失数量；HTTP成功但数据不完整不得显示为完整成功 |
| 15分钟完整性明细 | 按设备和时间段查看每个15分钟时刻的应到/实到情况；显示电表名称、外部地址、缺失时刻及关联运行记录，支持过滤未恢复缺口 |
| 告警提示 | 工作台总览和任务列表提供醒目的活动告警标识，可进入缺失明细；即使HTTP请求成功或返回空数组，缺失仍需告警 |
| 补数与恢复 | 根据缺失设备/时段创建补数任务，查看限流排队及执行进度；补齐并通过有效性校验后自动标记告警已恢复，保留发现、重试和恢复历史 |

完整性判定和告警规则：

1. 以该时间段内已纳入采集范围的电表清单及15分钟时间网格生成预期集合，不能用API实际返回的地址清单充当预期集合。`[12:00,13:00)`应检查12:00、12:15、12:30、12:45四个时刻；累计读数差分所需13:00边界点另行检查，不混淆区间记录数和边界读数要求。
2. 按“电表地址 + 时刻”逐项核对，分别统计接口返回记录覆盖率与有效`ZYGDNSZ`读数完整率；重复行不能补足另一个缺失时刻，只有记录但读数为空/无效也应告警。允许有效累计读数不变，不允许以缺行代表零用电。
3. 对已超过供应方延迟缓冲、到期应完成的时间段，在采集检查后持久化缺失告警并立即显示于工作台，不等待所有重试耗尽。尚在延迟缓冲内的时刻显示待到期，不作为已缺失告警；任务未执行、容器停机或请求失败导致的到期缺口也不能按成功处理，应在工作台展示采集状态及数据缺口。
4. 同一缺失点重复发现更新原告警而非重复创建；管理员确认仅表示已知悉，不等于数据恢复。补数后须重新核对，只有记录及有效读数齐全才恢复；恢复后再次缺失可重新激活并保留历史。
5. 一个小时4个区间时刻均齐全仍需核验小时差分的边界读数。缺失或无效数据不能静默补零、推进完整数据水位或生成完整小时账单；其他完整设备和时间段应可继续处理。
6. 验收样例：33台均纳入所测小时采集范围时，应到132条，实到116条，缺失16个设备时间点、涉及4台，完整率约87.88%。工作台必须列出这16个缺口并告警，而不是因`IsSuccess=true`或`Count=116`显示完整成功。

### 3.6 电表档案初始化任务

本版本增加管理员可操作的“电表档案初始化”功能。管理员在工作台提交任务，由独立采集容器调用`/NH2/AmmeterBasicInfo`获取档案，自动生成本地配置实体；无需用户逐台录入同一份档案。该任务只初始化档案及配置，不生成虚构电量或自动执行历史补数。

操作流程：

1. **获取与预览**：选择已配置的数据源，获取档案快照；显示外部地址、名称、区域、已有映射及冲突情况，支持全选或按电表选择。预览与确认后的创建结果关联同一任务，实际写入前再次校验并发冲突。
2. **填写必要配置**：能源类别选择系统已有的电能类别；管理员选择目标费用中心、是否计入统计、小时用量上下限，并可批量填写或逐表调整。来源档案未提供这些MyEMS必填业务配置，不能随意指定费用中心或猜测上限；未满足必填校验不创建无效业务表记录。空间、能源分项、产品及主从表等可选业务关系可后续配置，不按`AreaName`自动推断。
3. **确认并执行**：按选定档案创建或复用下表实体，逐表记录执行结果。新建的采集映射先保持未启用，管理员检查配置和采集起始时间后再启用；创建时间不作为历史缺数告警的自动起点。
4. **结果与后续配置**：工作台显示新增、复用、冲突和失败明细，并链接到现有计量表/测点配置页面；用户可补充业务关系、启用采集或另行提交电量历史初始化任务。

| 生成实体 | 字段来源和规则 |
|---|---|
| `tbl_meters`计量表 | 名称基于`AmmeterName`，生成本地UUID；能源类别、费用中心、是否统计及小时限值来自管理员确认配置。名称冲突时提示并要求确认唯一名称，不覆盖同名既有表 |
| `tbl_points`数据点 | 每台创建一个正向有功累计读数测点，绑定本数据源；`object_type=ENERGY_VALUE`、`is_trend=true`、`is_virtual=false`；JSON地址标识外部`Address`与字段`ZYGDNSZ`，单位、限值及倍率按已确认的计量口径和测点校验规则配置，不能直接将`TimesV × TimesA`重复应用到已换算读数 |
| `tbl_meters_points`表点关联 | 将生成或明确复用的计量表与该累计读数测点关联，重复执行不能重复关联；禁止误关联另一数据源的测点 |
| 外部电表映射表 | 保存来源数据源、外部`ID`/`Address`、本地`meter_id`/`point_id`及档案属性、配置状态、初始化任务和同步时间；作为后续电量采集的确定性映射 |

幂等、冲突与变更规则：

- 同一数据源、同一外部地址重复执行初始化，复用已创建的完整实体组合，不再次创建电表、测点或关联。并发初始化通过数据库唯一约束及任务互斥保护，不能仅依赖“先查询再插入”。
- 每台电表的计量表、测点、关联及映射在同一配置数据库事务中创建；失败回滚该台创建，其他成功电表保留。任务显示部分完成，失败项可单独重试，不能留下无映射的孤立实体。
- 来源已有映射时，校验本地实体仍存在且归属一致；失效映射、地址/外部ID冲突、疑似换表或本地已有候选电表时提示管理员，支持明确选择复用并校验现有测点，不按名称自动绑定或自动改绑。
- 后续档案同步更新外部属性和同步时间，不覆盖管理员设置的本地名称、费用中心、业务关系和启停状态；单次档案未返回某台电表也不能自动删除其本地配置或历史数据。
- 初始化、重试、复用和启用操作均记录管理员身份及逐表结果，仍受统一接口限流和管理员权限控制。

## 5. 开发前待确认事项

1. `ElectricQuantity`正式请求Body与Content-Type：公开规范描述JSON，本次测试记录的两个接口Content-Type不同，且测试记录没有完整请求体。
2. `valueType=SJZ`、取`ZYGDNSZ`作为有效累计读数已确认，不再作为待选方案。仍需确认计量单位、是否已包含PT/CT变比，防止重复乘倍率，并确认`ReadingDate`对应的累计读数时刻及回退/换表规则。
3. `startTime`/`endTime`的包含边界、服务端时区、跨日/跨年查询规则、最大查询跨度和最大响应记录数。
4. 33台档案中4个地址在所测一小时无电量记录的原因；是设备停用/无数据还是接口漏数。
5. `AmmeterBasicInfo`的全部档案是否可无参数稳定返回，是否存在分页、总量上限及档案变更通知机制。
6. API Key有效期、调用主体授权边界和密钥轮换流程。测试材料包含认证字段，任何真实密钥均不应复制到代码或本计划。
7. 每个应到15分钟时刻必须有记录、缺失必须工作台告警已确认。仍需细化自动补数的重试上限、最长等待和升级处置方式，以及补齐后账单和碳排历史重算的业务批准人；本版本不静默接受缺失小时。

## 6. 初步容量判断

70台按96个15分钟点/天估算为6,720条/天。按供应方确认的空地址全量查询能力，每小时一次电量批量查询约24次/天，另加低频档案同步；接口频率限制不是预期瓶颈。单纯数据量也不构成明显数据库压力。

本次单小时样本返回116条，不能据此证明全量70台、长期补数跨度或生产稳定性；初步应先按“测试档案数33台、覆盖29台”验证缺数处理，再以70多台做端到端持续试运行。容量结论不是未经压测的生产性能承诺。
